# 傳音玉符：靈石貨幣

## 品級與記帳單位

靈石只有下品、中品、極品三等，不另設上品。

| 品級 | 等值下品 |
| --- | ---: |
| 1 枚下品靈石 | 1 |
| 1 枚中品靈石 | 100 |
| 1 枚極品靈石 | 100000 |

因此 1 枚極品靈石等於 1000 枚中品靈石。新交易的 `amount`、商品的 `price`、錢包 `balance` 均以「下品」為基準，不能把中品或極品的面額直接寫入下品數字。

品級換算只做一次。例如輸入 `2 中品靈石`，解析後存入 `200`，後續付款、退款、顯示與保存都讀這個 `200`，不再乘 100。

## 輸入與顯示

新金額必須能精確換算成整數枚下品。

| 輸入 | 下品記帳值 | 結果 |
| --- | ---: | --- |
| `25` | 25 | 未註明品級時視為下品 |
| `2 中品靈石` | 200 | 接受 |
| `0.5 極品靈石` | 50000 | 接受 |
| `1.25 中品` | 125 | 接受 |
| `1極品 2中品 3下品` | 100203 | 接受 |
| `0.001 中品` | — | 拒絕；不足一枚下品 |
| `12.34 下品` | — | 新金額拒絕；歷史尾數另行保留 |
| `2 上品` | — | 拒絕；沒有此品級 |

介面顯示可分解品級，例如 `100203` 顯示為「1 枚極品靈石 · 2 枚中品靈石 · 3 枚下品靈石」。這只是顯示方式，沒有額外兌換手續費或價差。

## 舊資料與尾數

舊版本以兩位小數保存虛構金額。升級不把原有數字乘以 100，不增加、截掉或補足任何金額。

例如：

- 舊餘額 `520` 仍是 `520` 枚下品，顯示為「5 枚中品靈石 · 20 枚下品靈石」。
- 舊餘額 `520.05` 仍是 `520.05`，顯示為「5 枚中品靈石 · 20.05 枚下品靈石」。
- 舊價格、已付款金額、未完成的交易、退款及其交易 ID 保持原值。
- 「舊帳尾數」是對歷史小數的相容處理，不是第四種品級，也不會自動進位成一枚下品。

歷史尾數可在原有交易領取、退款或購買舊目錄商品時結算。新的金額輸入與新商品生成仍使用整數下品。重新載入或重試同一交易不應重新發款；舊交易的 ID 與 fingerprint 不得因改顯示名稱而更換。

正文的舊 `元`／`¥` 購買語法保留原解析數值及原有事件描述，因為舊取得紀錄的 fingerprint 包含描述文字。這可避免升級後把既有紀錄錯認為修改過的交易。新「萬寶閣」及明確靈石語法會使用靈石描述。

## 範圍與運算

核心錢包上限 `SPIRIT_MAX` 為 **99999999 枚下品**。餘額可為零；新商品價格範圍為 **1–99999999 枚下品**。單項功能若有較低的單筆限額，應將該限額明確傳給解析器，並讓輸入框、模型規則與執行端使用同一值。

轉換使用 `BigInt` 計算比例。既有兩位小數在結算時先轉成整數百分位相加，最後才回到既有儲存 API 的數字表示。超出限額、安全整數或可回復的精度範圍時拒絕操作，不截斷、不四捨五入、不改成免費商品。

外部服務的真實金額和額度不屬於此設定。Fish Audio 的 API 餘額、ElevenLabs 的字元積分、NovelAI Anlas 及付費繪圖提示仍使用服務原本的單位。

## 整合 API

`core/currency.js` 提供：

- `parseSpiritAmount(value, unit = 'lower', {zero, max})`：把指定品級轉成整數下品。單位可用 `lower`、`middle`、`supreme` 或中文名稱。
- `parseSpiritText(value, {zero, max})`：解析裸數字或帶品級文字；裸數字的單位為下品。
- `formatSpiritAmount(value, {compact, legacyNote})`：只讀顯示，不改帳本。`legacyNote: true` 可標示舊帳尾數。
- `addWalletAmount(left, right, {signed, max})`：精確相加，扣款使用負的 `right`。不得先做一般浮點加法再交給此函式。
- `legacyWalletAmount(value, {zero, max, signed})`：只供已存在的兩位小數金額、舊商品和原交易結算。
- `SPIRIT_CURRENCY_RULE`：可加入生成提示詞的完整品級及記帳單位規則。

`core/wallet.js` 的 `walletAmount(value, {unit, legacy})` 預設按新整數規格驗證；處理明確既有交易時才傳 `legacy: true`。

新商品生成仍可使用原有 JSON 欄位，僅改變金額規格：

```json
{"items":[{"name":"凝氣丹","description":"恢復靈力。","price":200,"kind":"items"}]}
```

舊公開商城介面的 `{title,text,amount}` 形狀也保留，`amount` 同樣以整數下品輸出。生成清單本身不會扣款。

## 正文取得記錄

「萬寶閣」「万宝阁」「萬寶商城」「万宝商城」均可作為商城名稱識別。明示 `以2中品靈石購買了「凝氣丹」` 時，事件價格是 `200` 下品；敘述沒有價格時，解析器保留「未記載價格」，不自行補造金額。

後續仍沿用原有取得流程：同名目錄中已有明確價格時可依既有目錄價格處理；既無正文價格，也無已知目錄價格時，不因記錄物品而扣除猜測的金額。假設、打算、引述、程式碼、助手代述及第三人的購買不會替使用者取得物品。

明確寫出無效靈石品級或不能精確換算的價格時，該項取得會報錯並停止，不把無效價格降級為「未定價」後繼續取得。
