# 傳音玉符 0.13.1／角色信息 CSB 1.3.0

本版修正目前場景的在場／離場狀態，保留 0.13.0 的角色庫、無 TTS 介面及劇情時鐘。

## 手動決定角色是否在場

在「角色信息」或角色管理的角色卡，使用在場設定選單；編輯角色時也能設定：

- **跟隨劇情**：採用正文更新及已確認的掃描結果。
- **固定在場**：這段聊天內保持在場，模型或掃描不能覆蓋。
- **固定離場**：這段聊天內保持離場，模型或掃描不能覆蓋。

固定設定只套用於目前聊天；切回「跟隨劇情」會重新顯示正文判定。編輯年齡、身分或其他欄位，不會順便把舊在場狀態寫回。角色離場不會清空人物資料。

最新正文狀態卡會同步目前的手動設定，即使後面已有使用者訊息。較早回合仍保留當時的狀態，不把現在的位置改寫到歷史情節。

## 掃描時核對在場狀態

「掃描正文／AI 填表」新增預設開啟的在場判定。掃描角色資料與判定是否在場分開處理，因此即使選擇「只新增角色、補空白欄位」，仍可修正已有角色的在場狀態。

結果顯示原狀態、建議狀態和原文依據，可獨立勾選是否採用。固定在場／離場的角色會標明手動固定，掃描不能覆蓋。無明確依據時顯示無法判定並保留原值。

判定以掃描範圍內最新場景為準。僅被提及、回憶、假設、計畫前往或透過玉符遠端傳訊，不直接視為目前實際在場。本機掃描處理明確結構與明確的進出場文字；需要理解較複雜敘事時，使用 AI 填表並核對引用。

掃描後若正文、回覆分支、角色資料或聊天已改變，舊結果不會直接套用。角色的持久資料保留；場景在場狀態跟隨其來源分支。

## 身份與資料相容

模型可使用完整 `present` 名單，或在既有角色條目中明確更新布林 `present`。只改一人的在場狀態不會清空其他人的狀態。

姓名或別名能唯一對應既有角色時，會沿用既有 ID；缺少姓名且無法識別的新 ID 仍會提示核對，不猜測人物。名單中有無法識別的人，不會因此把其他人全部標為離場。

原始聊天正文不會被改寫，角色欄位、手動資料及備份仍可接續使用。

## 更新

若要直接修補手機上已安裝的角色信息，下載本版 `Install_CSB_1.3.0.cjs` 到手機 Download，再於 Termux 執行：

```bash
node /storage/emulated/0/Download/Install_CSB_1.3.0.cjs
```

工具會尋找既有酒館，先核對程式版本並備份，再更新內建、獨立及使用者目錄內找到的 CSB。若偵測到自訂修改或找不到唯一的酒館位置，會停止並說明原因。此工具只修補 CSB，不變更小手機主版本號，也不修改聊天與角色資料。完成後用原本方式重啟酒館並重新整理頁面。

使用本次 Termux 上傳腳本更新原 GitHub 倉庫，接著在酒館更新「傳音玉符」並重新整理，再到「玉符接入」更新配套規則至 0.13.1。上傳腳本關閉 Git 分頁器，顯示修改清單後會自動繼續，不必再按 `q`。

**若另外安裝了獨立「角色信息 · CSB」，必須把那一份也更新至 1.3.0。** 執行中的獨立插件仍優先於小手機內建版本；只更新小手機不會覆蓋另一個插件目錄。可用本版原始碼的 `companions/csb-character-state` 更新獨立插件程式，保留酒館資料。
