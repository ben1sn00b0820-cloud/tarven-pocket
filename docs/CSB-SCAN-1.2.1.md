# CSB 1.2.1：修正未生成正文卻被阻擋掃描

## 原因

上傳的 0.12.0 套件內含 CSB 1.2.0。其 index.js 對所有 GENERATION_STARTED 直接設 busy=true，只有結束／停止／換聊天才清除。這個事件還可能來自提示詞試算、背景 quiet 請求或提前退出的生成流程，不能單憑事件判定正文仍在生成。ScanService.run 又直接用 busy 阻擋本機及 AI 掃描，因此會出現截圖的提示；同一旗標也會阻塞自動掃描排程。

已核對 SillyTavern 官方 release 分支 public/script.js（blob SHA 777a2d5983a6283ef9b26726e75192da1e3f3cea）：Generate 發送 GENERATION_STARTED 時帶有 type、options、dryRun；dryRun 在組裝完提示詞後直接返回。無須真正發出正文模型請求，就能留下舊插件的 busy 旗標。這是可重現的程式缺陷，但沒有使用者裝置事件記錄，不能斷定截圖當下是哪一條路徑觸發。

官方程式：https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js

## 修改

- 排除 dryRun、quiet 與 impersonate 的正文鎖定；背景請求不會解除另一個真正正文的保護。
- 核對即時宿主生成旗標及串流狀態；宿主介面不可用時使用停止按鈕／生成標記備援，最後才使用事件狀態。
- 真正生成的開始有短暫寬限，避免宿主尚未設旗標便誤認閒置。只在讀到閒置狀態後解除，不因生成很久就強制解鎖。
- 等待生成時每 500ms 輕量檢查狀態；完成後恢復排程，閒置時不持續輪詢，不逐字掃描正文。
- 自動掃描遇到生成先延後，不把該則訊息記為已掃描；套用預覽或接收 AI 分析結果時再次檢查生成狀態。

原資料結構、欄位、聊天內容與角色資料不遷移、不清空。

## 手機快速修補

下載 CSB_Fix_1.2.1.cjs，存入手機 Download 資料夾，在原本的 Termux／SillyDroid 終端執行：

```bash
node /storage/emulated/0/Download/CSB_Fix_1.2.1.cjs
```

如果酒館不在預設位置，在命令後面加實際路徑，例如：

```bash
node /storage/emulated/0/Download/CSB_Fix_1.2.1.cjs "$HOME/SillyTavern"
```

修補器只尋找已安裝的 CSB 1.2.0／1.2.1，包含傳音玉符內建副本、另裝的獨立 CSB 與個人擴充位置；根據 manifest 辨認，不要求資料夾一定叫 tavern-pocket 或 tarven-pocket。它會先檢查所有目標並備份 5 個受影響檔案，才替換程式；沒有目標或版本不同就停止。沒有網路下載、沒有新增第二份插件，也不更動聊天／帳號資料／.git。發生寫入錯誤會嘗試還原原檔，備份位置顯示在終端。

修補成功後，以原本方式重啟酒館，再重新整理酒館頁面。角色信息的設定／紀錄版本應為 1.2.1。小修補不改傳音玉符主版本號；下載完整原始碼則為 0.12.1。

若頁面仍顯示舊版本，先確認已重新載入，以及修補器列出的目標是否包含正在啟用的獨立 CSB。傳音玉符會優先沿用已啟動的獨立 CSB，只更新內建副本不一定有效。

## 手動安裝

完整原始碼位於 tarven-pocket。先備份既有插件程式，將資料夾內容覆蓋到原插件目錄，不要另建第二個擴充。已另裝 CSB 者，同時以 companions/csb-character-state 的內容更新原 CSB 目錄；或直接使用上面的修補器。不要刪除聊天資料，不需要重建人物、換世界書或換角色卡。本修補不需要重新匯入正則。

## 驗證與限制

執行既有傳音玉符與 CSB 單元測試、Chromium 掃描介面測試及安裝器檔案系統測試。新增測試涵蓋 dryRun、quiet 開始時尚未鎖定宿主的事件順序、漏結束事件、真實串流／非串流生成、長生成保護、預覽寫入時的生成檢查及自動掃描重試。詳細結果見 VALIDATION-CSB-SCAN-1.2.1.json。

瀏覽器執行真實插件程式，酒館宿主與模型回覆為測試替身；安裝器使用臨時目錄模擬 Termux／SillyDroid。未在使用者實體手機或付費模型上測試。無即時狀態介面的特殊酒館分支仍依賴事件備援；宿主自身卡住且仍宣告生成中時，插件不擅自取消其請求。

此交付為可下載修補與原始碼，不代表 GitHub 上的版本已更新。
