# 傳音玉符 0.12.0 / 角色信息 CSB 1.2.0：正文掃描與 AI 填表

本次為可下載安裝包，尚未推送 GitHub。既有 GitHub 主分支最後核對為 0.11.0。不要把按下「檢查更新」當成已安裝本版。

## 哪一份需要更新

已獨立安裝 CSB：用 `CSB_角色信息_v1.2.0.zip` 覆蓋原 `csb-character-state` 擴充程式。原傳音玉符 0.11.0 可沿用同一個 CSB bridge，不需要重建角色卡。只更新傳音玉符的內建副本、卻繼續啟用舊獨立 CSB，不會出現新功能。

僅使用傳音玉符內建 CSB：用完整原始碼包更新原來的 `tarven-pocket` 程式目錄，或沿用原離線安裝方式執行 0.12.0 安裝器。不要另裝第二份小手機。Git 安裝目錄須保留 `.git`，本次本地檔案變更可能讓往後 git 更新要求先處理變更。

兩種方式都先匯出現在的 CSB 完整備份及玉符備份，再覆蓋程式、重啟酒館並重新整理。聊天、角色資料、靈石、聯絡人沒有重設。本次不需要匯入《玄衡界》初始狀態，不需要換角色卡或開新聊天。


## 為何原版沒有讀懂正文

1.1.0 的自動更新讀取 `<CSB_UPDATE>`，不會把任意敘事句子自動轉成欄位。模型漏寫該區塊，或只產生裝飾用 HTML，資料庫沒有可套用的更新。

原 `text()` 驗證以同一訊息回報「不是字串」及「超過 100 字」。因此缺少新角色 name、輸出 name 物件、對已有角色亂換 ID 都可能顯示「新角色姓名必須是 100 字以內」。沒有出錯回覆的原始內容，不能斷言使用者這一次屬於哪一種。

1.2.0 分開回報：缺少 name、空白姓名、型別錯誤、實際字數超限、疑似段落／多姓名／標籤、姓名與 ID 衝突。100 字保護仍在，不將整段敘事截斷成假姓名。已知 ID 可省略姓名；姓名或唯一別名可把變動 ID 對回既有角色。模糊重名不擅自合併。姓名錯誤的個別條目會略過，其他身份合法的更新繼續處理；欄位本身仍需通過原有更新驗證。

## 手動掃描入口

傳音玉符 → 角色信息 →「掃描正文」／「AI 填表」。

也可輸入 `/csb` → 角色庫 →「掃描正文」／「AI 填表」。這是插件按鈕，不是要求模型在故事裡畫一個按鈕。

掃描面板提供：最新 1 則、最近 5 則、最近 20 則、本聊天最多最近 60,000 字元；可選全部人物或指定一位人物。預設只讀 AI 已送出的原始正文，可自行勾選包含使用者已送出的訊息。不讀輸入草稿、推理區、舊 swipe 或整本世界書。

本機掃描不呼叫模型：讀 CSB_UPDATE、CSB21、姓名標籤及帶引號的明確自我介紹。它不會猜出任意小說句子中的所有人名。使用者應選 AI 模式分析普通敘事。

AI 填表使用酒館當前連線的文字模型，以 generateRaw 傳送本次文字、實際啟用欄位及文中相關人物資料；不需另填一組 API 金鑰。每批正文最多 10,000 字元，按批順序呼叫；長範圍可能需要多次模型請求。模板超過 250 個啟用欄位會要求先縮小範圍，不假裝無限上下文。模型必須輸出 JSON 並附每項欄位的原文引句，結果仍需使用者核對。沒有配置可用的模型或 generateRaw 不可用時會顯示錯誤，不改動資料。

## 預覽與寫入

「只新增角色、補空白欄位」是預設。看到候選姓名、原值、新值及原文依據之後，勾選角色與欄位，按「套用勾選結果」。新角色可以修正姓名；既有角色姓名不可由掃描改名。

「預覽明確變更」允許列出已有欄位的差異，但覆蓋已有值的勾選框預設不勾，需逐項選擇。鎖定欄位、初始化後固定且已有值的欄位、僅手動欄位均保持原值；未知、null、空字串不清空舊資料。沒有依據的數字與秘密不應填入。角色只是被提及，不會因此被標為在場。掃描不修改原訊息，不刪除其他人物，也不重新計算靈石或執行轉帳。

語法及引句檢查不是語意真實性的保證。模型仍可能把一句話理解錯、填錯人物或漏掉角色，所以預覽是必要的保護，不是裝飾。未知新欄位不會擅自加入模板。

重掃依姓名／唯一別名／原 ID 去重。點兩次套用不重複寫日誌。生成期間、來源編輯、分支變更、聊天切換或資料在預覽後被修改，都有防過時寫入檢查。取消會丟棄未採用結果並停止後續批次，但已發出的模型請求可能仍計費，不能保證服務端中止。

## 自動偵測與自動建檔

角色信息 → 管理角色與欄位 → 設定／紀錄 →「自動掃描正文」。

- 本機（預設）：完整回覆完成或編輯後，只掃該則文字中的明確姓名／格式化欄位；不逐字掃描，不花模型額度。自動本機掃描只新增及補空白。
- AI：每輪完成後額外分析該則普通正文。預設只產生待確認結果，可開啟掃描面板查看。
- 關閉：停止額外正文掃描；原 CSB_UPDATE 協定更新仍保留。

再勾選「AI 結果自動新增／補空白」，AI 結果會直接建立新人及補未知欄位。此模式不改掉已有值、不處理在場名單，但仍可能接受模型誤判，需自行承擔核對責任。預設不開，以免偷偷增加用量及建立錯誤資料。

## 效能與資料邊界

只在完成訊息事件後排程，不監聽輸入框或逐字串流做 AI 請求；同一回覆去重，一次最多一個掃描請求，批次間讓出 UI 執行時間。候選最多 300 人並提供超限診斷。讀取 chat 原始文字，不掃 DOM，不會把裝飾狀態卡或其他插件畫面當成人名。

使用者確認的掃描結果寫入原本持久資料日誌。既有備份格式與欄位 ID 不變，既有進度可續用。
